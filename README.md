1. 备份网站和完整数据库。
2. WordPress → 插件 → 安装新插件 → 上传 `sports-meet-v2.1-plugin.zip`。已有Sports Meet时选择替换并启用。不要上传主题ZIP或包含两个ZIP的合集。
3. 可到外观 → 主题上传 `sports-day-v2-theme.zip` 并替换启用，以更新默认菜单。其他主题也支持短代码。
4. 到运动会计分 → 相册与网站设置 → “创建／补齐网站页面”，补齐报名名单及裁判工作台。现有页面内容不覆盖。
5. 在WordPress“用户”中给每位裁判建立独立账号，角色选“运动会裁判”。普通相册用户用订阅者。

升级不会删除旧队伍、运动员、旧计时成绩或相册。旧成绩缺少预／决赛及确认参赛记录，保留在“旧版成绩（只读）”，不会自动当作2.0赛果计分。已有运动员和项目可继续用于报名。

环境：WordPress 6.4+、PHP 8.1+、mbstring、支持InnoDB及外键的MySQL 5.7+/MariaDB 10.3+；数据库有建表权限。相册另需GD及exif。多站点仅支持各子站单独启用。

## 报名CSV和编辑

新版CSV无需报名编号，固定6列：

`university,name,category,event,kind,relay_name`

分别填写所属高校、姓名、四种组别之一、项目名称、individual或relay、接力队名称（个人留空，未编接力队也可留空）。一个人报名多个项目写多行，前三列一致。保存为UTF-8 CSV。

重复导入按“所属高校＋姓名＋组别”匹配已有人员，不会重复增加相同项目。若同高校、同姓名、同组别已有多人，导入会中止并提示核对，不会猜测合并；这些同名人员可在后台分别编辑。

CSV导入为添加／补充项目，不会取消文件中未出现的旧报名。取消项目请编辑报名并取消复选框。仍兼容2.0旧8列CSV，但新导出和模板都不显示内部编号。

项目会随所选组别筛选，项目配置的性别和组别限制仍在提交时验证；请按各组比赛规程选择。各年龄／性别如须分别排名，应建立相应项目。新建项目、所属高校管理分别在“项目”页和报名页的“所属高校管理”区域。


## 比赛日：检录发号

裁判在前台工作台选择检录，按队伍、姓名、报名编号或已发比赛号码查找，再输入比赛号码。

- 比赛号码全场唯一，范围1至99999999；001与1视为同一号码。
- 数据库唯一索引＋事务保护。多裁判同时抢同号，只有一个成功。
- 同一运动员带版本检查，旧页面不能覆盖他人刚发的号码。
- 普通裁判不能改已发号码，需要改号时由管理员操作。

## 预赛／决赛

管理员先在“预赛／决赛 → 生成名单”选项目及预赛或直接决赛。

- 个人默认单组预赛取前三。确需分组时勾选“个人预赛也分组”，按每组前三晋级。
- 接力按填写的每组队数分组，每组前二晋级。
- 分组按报名顺序。首个预赛提交完成前，管理员可用条目ID调整到目标组；移动会清除该条目的暂存确认和名次。
- 单轮／决赛最多200个参赛对象，过多时按性别年龄拆项目或合理分组。

裁判选择对应项目的预赛组／决赛，名单列队伍、姓名／接力队、号码、确认、名次。勾选实际参加者；前三填1、2、3，其余留空。少于3名确认参赛者，按实际人数填连续名次。

确认个人参赛前须已检录；接力确认前8人都须已检录。名次暂不支持并列，须现场判定后填写。

“暂存”不公示、不计分、不晋级。“提交本轮完成并计分”后锁定本轮。每组预赛完成时自动加入晋级者，所有预赛组完成后才允许录入决赛。决赛只另加名次分，不重复参赛分。

同一轮被其他裁判更新时，旧表单会被拒绝，须刷新后核对，不会覆盖或混合两份表。页面不自动实时刷新。整轮无人出赛时，全部不勾、名次留空，在专门区域输入DNS提交为0分。

已完成轮次仅管理员可输入REOPEN撤回更正，重新提交才恢复公示。撤回预赛会重建决赛并清除尚未完成决赛的暂存资料；决赛已完成须先撤回决赛。后台日志记录操作人、时间及变更。

## 现场跨队接力

管理员或裁判可在检录后打开“接力组队”，输入8个比赛号码（英文逗号分隔）及接力队名称。编辑时填写现有接力队ID及完整8人名单。可跨所属高校，须满足年龄组和男女比例；生成该项目比赛名单后不能临时换人或加队。

混合队是参赛单位，运动员所属高校不改变；全部参赛分和均分后的名次分计回各人所属高校。

照片沿用1.1功能：JPG/PNG/WebP，每批5张，每张≤12MB或主机上限，校正方向、保持比例缩到宽≤1920高≤1080、小图不放大，JPEG质量82、去EXIF、不留大图。默认审核，待审照片仅本人和管理员可读。压缩图片在专用数据库表，不进入媒体库。

## 备份、清空与限制

使用完整数据库＋网站文件备份；CSV不是完整备份。停用或删除插件不会自动删数据。

**旧聊天中的1.1清空SQL不能用于2.0**。本包CLEAR-TEST-DATA.sql是2.0模板：先备份、暂停裁判及上传、核对替换表前缀后执行；会清掉全部比赛、报名、号码、照片和日志，保留用户、页面和规则，恢复预设接力项目，不重置ID。

2.0共有14张带sm_前缀的独立表。不要删除WordPress核心表。规则、页面关联及照片审核设置另存在WordPress选项中。

首页、名单、成绩、排行榜、裁判及上传页面应排除整页/CDN缓存，特别不能缓存登录用户页面。刷新后看新成绩。照片建议PHP内存384M、upload_max_filesize 12M、post_max_size 64M。

本版没有并列名次、按计时递补、自动跑道分配、短信或多场运动会赛季管理。旧成绩保留但不自动转换。尚未在用户cPanel和主题／插件组合上部署，浏览器视觉核验未完成；正式比赛前请用真实裁判账号演练。测试记录见VALIDATION.md。

## 2.4.6 自动更新
更新来源：https://github.com/NZSteven/sports-meet 。安装并进入后台后自动开启本插件自动更新一次，之后尊重管理员开关。WordPress 定期读取 main/update.json，并下载其中 commit 对应的固定版本ZIP。只同步代码，不同步报名、成绩、照片和数据库。
发布步骤：先检查并提交新版全部插件文件；再将 update.json 中 version 和 commit 指向该提交。不要把测试账号、主机配置、数据库或照片放入仓库。只有代码提交不等于发布，更新清单后才对网站提供新版。首次需手动上传本包替换2.4.5或更旧版，并进入后台。定时任务和主机写权限必须正常。可在插件列表关闭自动更新。
